权威：US-08–10、US-18。Copilot 最小版**只依赖 M0 AI 日志**，PRD 允许提前到 M2。Release v1 **依赖 M2 Jira**。清单见 [ai_context.md](../ai_context.md) §4.4。

## 硬约束

- 不自研压测引擎（包装 Locust/k6）。压测走统一 TestRun 10 态。
- 白名单外 DENY，不进审批。高危走 `perf_high_risk` + FR-04。
- kill switch：关停 L1；恢复 L3。压测 60s 内停施压（PRD C.4）。
- Copilot 最小版：只读技能、全量日志、权限感知、服务端会话。越权 DENY。**API-194/195 技能写与商店 = M4 Out of Scope。**
- AI 草稿禁止自动 `release_push`。

## 切片要点

**S-M3-01 FR-11**（**完成**）  
依赖：locust==2.46.4（用户批准 + 审计 MIT/活跃/无通告 + `uv add`，锁文件变更独立 commit）。`perf_worker.py` 子进程（**fire-and-forget**：executor 派生后即返回，收尾归 worker——否则 START 的 BackgroundTasks 内联等待造成受理死锁）：生成 locustfile → `locust --autostart --web-port --json-file --csv` 子进程 → 监控环（5s 轮询：STOPPING/`stop_signal_at`、kill switch `tightened_modules` 含 `performance`、`/stats/requests` breach 检测、心跳 15s）→ psutil 采 CPU 判「施压机饱和 vs 目标慢」（B.10）→ `perf_report` Artifact + CaseResult → 终态 + 释放配额 + 门禁评估 + 排队晋升。受理：perf 用例须同质且 script 源；**白名单外 HT-POL-002 直接 DENY 不建审批**（AC-051，白名单=场景 params `perf_whitelist` 前缀匹配 TARGET_ENV）；同场景在途 → 受理成功 PENDING+`perf_queued`（AC-054，不并行施压），终态由 worker 晋升一个排队兄弟（单一调度 Owner）。高危（scenario/step `side_effect_level>=L2`）→ RUNNING→WAITING_APPROVAL + 自动建 `perf_high_risk` 审批（统一 `compute_param_hash`；批准→EXECUTED+CAS 回 RUNNING 续跑；拒绝/过期→CANCELLED；worker 侧 TTL+60s 自取消兜底）。并发预算 `OrgQuota.perf_concurrency_in_use`（Alembic 0023），VALIDATING 占用/终态释放，不足 run FAILED `perf_quota_exhausted`。PerfBaseline API-056–059（test_assets，同场景唯一活跃 partial unique + CAS 停用旧活跃 + 对比投影）。P16：发起表单（白名单/并发/时长/排队提示）、基线创建+列表、kill switch 入口（module=performance）。AC-052 kill 演练实测 6s 内 CANCELLED（<60s）；无自动重试（AC-053）断言于 FAILED `perf_quota_exhausted` 路径与 worker 单次执行。残留：真实目标系统 E2E 未做（测试以 loopback+失败请求冒烟）；run_time>60s 的长时压测未实测；kill switch 模块码 `performance` 为实现约定；Locust 分布式/多进程模式未用（单进程 worker）；p95/error_rate 进门禁属 S-M3-02。
