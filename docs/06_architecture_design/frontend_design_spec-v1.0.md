## 1. 范围与职责边界

### 1.1 前端负责（UI / 页面状态 / 本地交互）

1. **UI 渲染**：P01–P25 共 25 页；三个关键页面（审批中心卡片、TestRun 详情、执行发起页）严格按 05 §4.3 结构约束与 C2 §2.3 / C3 §2.2 分区布局实现（见 §5.2）。
2. **页面状态渲染**：全部页面按 §5.1 状态基线（七态 + 链路特殊态）呈现；状态机类对象（TestRun / ApprovalRequest / ReleaseTask / ExecutionEnvironment / TestCase）只渲染服务端下发的状态，前端不推演状态迁移结果。
3. **本地交互**：表单与即时校验、组件联动置灰、diff 查看器、折叠展开（参数哈希）、Trace 回放控件、轨迹时间线、聚类人工修正编辑、列表筛选 / 排序 / 分页（一律进 URL，可分享可回溯）。
4. **实时呈现**：SSE 进度流（执行进度、报告生成进度、超大报告解析进度）的订阅与渲染。

### 1.2 前端不负责（服务端职责，前端只呈现结果）

| 职责 | 归属 | 前端行为 |
| --- | --- | --- |
| 状态机迁移触发与裁决（TestRun 迁移以 problem_model 的 canonical transition registry 为唯一来源，不手写边数；审批 consume、Release 推送） | 服务端治理面 | 只发起用户动作请求 + 渲染服务端状态 |
| Policy Gate 裁决（ALLOW / DENY / REQUIRE_APPROVAL / REQUIRE_REAUTH） | 服务端（FR-17） | 渲染裁决结果；置灰 / 引导仅为呈现 |
| 四眼校验、行锁防双执行、anti-TOCTOU 参数哈希复核 | 服务端（05 §2.3） | 发起人本人打开卡片时「批准」置灰（C2 §3.4）；服务端必须独立复核 |
| 聚类算法、规则聚类 fallback、脱敏管道 | 服务端（A2 契约） | 渲染 7 值枚举 / confidence / 脱敏后内容 |
| 幂等、重试、补偿、外部写 | 服务端 / 连接器 | 渲染外部资源引用与失败原因 |
| 权限判定 | 服务端（FR-01，viewer 只读） | 路由级只读呈现 + 无权限态；不可作为安全边界 |

产品原则对齐（README 第 1 章）：**AI 提议、策略裁决、工作流执行**——前端呈现提议与证据，不实现裁决与执行；**Evidence over eloquence**——关键结论必须可点击到证据（FR-07 / README 7.11）。

### 1.3 技术基线（引用 Stage 0 决策，不新增）

React + TypeScript + Vite（纯 SPA）· Tailwind CSS + shadcn/ui · TanStack Query（服务端状态与缓存失效）· Zustand（本地 UI 状态与 SSE 订阅存储）。

**路由库已定为 React Router**（2026-08-29 修订）：原表述「在 Stage 11 初始化时按 AI 红线 R4 依赖审批流程确定」已作废——该依赖已完成 R4 审批并前移至 Stage 6 冻结，锁定版本与审计见 [tech_stack_decision-v1.0.md](tech_stack_decision-v1.0.md) §3.3/§4.3 与 [ADR 0009](adr/0009_technology_stack_freeze.md)。约束一并冻结：**只用其路由与 URL 状态能力，不启用 loader/action 数据层**——服务端状态统一由 TanStack Query 承担，避免两套并行的数据获取与失效机制对同一份领域数据各自缓存（那会制造 §1.2 与 frontend_backend_boundary_spec §3.3 红线 1 所禁止的「前端自行推演状态」）。本规范仍只约束路由结构（§3），不规定具体路由 API 用法。

## 3. 页面结构层次（IA → 路由树）

路由为本规范分配的实现约定（kebab-case，与仓库 API 命名规范一致）；**页面集合与归属以上表为准，路由变更不影响页面编号**。

  ├── overview          P02 项目总览（默认重定向目标）

  ├── environments      P15 的项目过滤视图（Admin 或 Projects 双入口，同一页面）
  ├── integrations      P03 集成（项目级绑定）
  └── settings          P04 项目设置

  ├── kickoff           P08 执行发起页
  ├── runs              P09 TestRun 列表

  │       └── agent     P14 Agent 任务详情（execution_source=agent 型 run 专属视图）

### 4.2 全局跳转规则

1. **跨租户 / 不存在资源**：一律呈现「资源不存在」（404 语义），不区分 403，不泄露存在性（PRD §2.3，C1 ④#19 / C4 ④#18）。
2. **等待态滞留可见**：WAITING_APPROVAL / WAITING_EXTERNAL 的 run 在工作台「进行中 TestRun」与 TestRun 列表持续可见并显示滞留时长（05 §2.2 裁定 5）——前端不得因长时间等待隐藏或折叠该类卡片。
3. **无自动重跑入口**：TIMEOUT / Agent incomplete 终态只提供人工重新发起入口（12-PRD §7.1、FR-19；C3 ④ 自动重试适用性矩阵）。

| 全局 | AI 降级横幅（不静默）；404 呈现（§4.2） | 12-PRD §7.2 · §2.3 |

### 5.2 三个关键页面与强约束组件的结构（分区顺序冻结）

**审批卡片（P10，05 §4.3 约束 1 = C2 §2.3 ASCII 布局）**：自上而下——〔参数被修改时〕红色警示条 → 区 1 动作与目标资源 → 区 2 前后 diff → 区 3 数据来源与模型 / Skill 版本 → 区 4 风险等级 L0–L4 色标 + 成本估计 → 区 5 回滚能力说明（无回滚能力必须声明）→ 区 6 参数哈希（默认折叠、点击展开核对）→ 操作区「批准 / 拒绝（附理由）/ 修改后重新提交」。**分区顺序不得调换**；九要素缺一不入队（服务端校验，前端按 card_payload 全量渲染）。

**TestRun 详情（P09，05 §4.3 约束 2 = C3 §2.3）**：页头状态机进度条（10 态映射；WAITING_EXTERNAL 仅 external_ci 型出现；**WAITING_APPROVAL 高亮并可跳转审批中心**）→ 聚类报告区（每簇五要素：类别标签 + confidence + 阻塞判断 + 证据链接 + 人工修正入口；「无法判断项」独立区块逐条可点开；「修改历史」）→ 用例结果表（CaseResult / StepRun 下钻）→ 证据查看器（截图 / 视频 / Trace 切换 + Trace 回放）→ execution_source 徽标。

**执行发起页（P08，05 §4.3 约束 3 = C3 §2.2）**：三层自上而下**顺序不可调换**——第一层模式选择（Script / Agent，选 Agent 显示受限说明四条）→ 第二层环境选择（仅 ACTIVE 可选；显示 health_status 与容量 / 配额）→ 第三层参数表单（引用型用例按 params_schema_ref 动态生成 + 定时配置）→ 操作区「发起执行」。

**Agent 任务详情（P14，C3 §2.4）**：轨迹时间线（每步动作 + 截图 + 工具调用，A8 结构）· 终止按钮 · 转脚本草稿入口 · incomplete 标记。

### 5.3 本地交互清单（纯前端逻辑，无服务端状态变更）

1. **动态表单**：按 `params_schema_ref` 生成引用型用例参数表单；提交前本地即时校验（不过校验未提交即可见），服务端 VALIDATING 校验失败原因在 P09 详情呈现（C3 ④）。
2. **联动置灰**：模式 × 环境组合——选 Agent 时外部 CI 置灰（一期不支持）；选外部 CI 时 Agent 不可用；DEGRADED / DISABLED / PENDING_APPROVAL 环境不可选并显示原因（C3 ②2.2 / 1.3）。
3. **查看器与折叠**：diff 查看器（区 2、heal_apply fixes 的 field / current / suggested）、参数哈希折叠展开、Trace 回放控件、证据三件套切换。
4. **聚类人工修正**：簇卡片「人工修正入口」本地编辑（类别 / 阻塞判断等）→ 提交留痕（correction_history，05 §2.5）；原值留痕展示。
5. **列表状态进 URL**：筛选 / 排序 / 分页一律同步到 URL query（page-inventory 填写规则）。

## 7. 响应式行为

> 上游（05 / 06 / 12-PRD）未定义响应式需求；本节为**工程约定**，锚定决策总纲的使用场景（企业内部自用、桌面工作场景、≤1000 用户），供当前不可用的 `../05_prototype/page-inventory.md`「响应式变化」列与 Prototype 阶段使用，Prototype 评审时确认。

1. **桌面优先**：≥1280px 为一等公民（全功能）；1024–1279px 可用（侧栏折叠为图标）；<1024px 降级为**只读浏览**（列表、报告、证据查看），不承诺完整操作。
2. **断点约定**：1280 / 1024 两档；不设移动端专用布局。
3. **关键页面降级规则**：

| 页面 | 1024–1279px | <1024px |
| --- | --- | --- |
| P01 工作台 | 卡片 2→1 列 | 只读卡片堆叠 |
| P05 / P09 列表 | 表格横向滚动 | 表格→摘要列表（行点击进详情） |
| P10 审批卡片 | 分区纵向堆叠（顺序不变） | 只读呈现（批准 / 拒绝引导回桌面操作） |
| P08 执行发起 | 三层保持纵向顺序 | 只读预览，不提供发起 |
| P09 证据查看器 | Trace 回放可用 | 截图 / 视频可看，Trace 回放不承诺 |
| P16 / P17 | 图表缩放、面板堆叠 | 只读 |

4. **不因响应式改变语义**：状态、审批、证据的呈现语义在各断点一致；仅布局降级。
