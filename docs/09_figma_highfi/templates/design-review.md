# 设计评审记录模板

用这份记录保存取舍，不要只保存最终截图。它连接 [PRD 到原型](../06-engineering-workflow/prd-to-prototype.md) 和 [视觉验收](visual-acceptance.md)。

## 空白模板

```markdown
# [项目/版本] 设计评审

日期：
参与人：
范围：
关联：[UI Brief](ui-brief.md) / [页面清单](page-inventory.md)

## 要解决的主任务
-

## 已确认决策
| 决策 | 理由 | 影响的页面/组件 | 负责人 |
| --- | --- | --- | --- |
|  |  |  |  |

## 被拒绝的方案
| 方案 | 未采用原因 | 何时重新评估 |
| --- | --- | --- |
|  |  |  |

## 风险与未决问题
| 问题 | 风险 | 下一步 | 截止时间 |
| --- | --- | --- | --- |
|  |  |  |  |

## 批准条件
- [ ] 主流程和失败恢复完整
- [ ] 组件状态已定义
- [ ] 权限和危险操作已确认
- [ ] 响应式和无障碍已评审

结论：未开始 / 有条件通过 / 通过 / 退回
```

## 已填示例摘要

- 决策：批量审批放在筛选栏右侧，始终显示选中数量。
- 理由：主管需要在比较后连续处理，避免去详情页逐条操作。
- 拒绝方案：将审批按钮放进每行更多菜单；风险是发现性差且批量任务变慢。
- 未决问题：部分失败是否需要自动重试，由后端定义幂等键后确认。
- 批准条件：默认、加载、空数据、无权限和部分失败均有原型；危险动作使用明确确认文案。
