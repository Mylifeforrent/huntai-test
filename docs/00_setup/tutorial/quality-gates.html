quality_gates · 质量门禁

模块位置：backend/app/modules/quality_gates/。管「结果能不能放行」：QualityGatePolicy（策略）+ GateEvaluation（评估结论）+ GitHub Check Run 三段式回写。

1. 两个对象，职责分离

对象内容纪律
QualityGatePolicy项目级阈值三件套 {min_pass_rate, max_p95_ms, max_error_rate} + 模式 report_only / blocking + version切 blocking 必须 confirm_blocking=true 显式开启（禁止隐式升阻断）
GateEvaluation单次评估：result（仅 pass/fail/waived）、threshold_details（逐阈值实测）、policy_snapshot、check_run_ref、waiver_approval_idappend-only；策略修改不改写历史评估（快照冻结）

2. 评估管线（一条，无独立分支）

TestRun 终态（script / external_ci / performance）→ schedule_gate_evaluation
  ├─ agent 来源        → 不建行，unevaluated_reason=agent_source
  ├─ CANCELLED/TIMEOUT → 不建行，cancelled_or_timeout
  ├─ 报告 partial      → 不建行，partial_report
  ├─ 项目缺策略        → 不建行，policy_unmet
  ├─ 压测 run 无指标   → 不建行，perf_report_missing
  └─ 否则实测：pass_rate + p95 + error_rate → details + result（pass/fail）
       → Check Run 三段式（queued → in_progress → completed）
            conclusion：pass→success；fail→blocking=failure / report_only=neutral
       → CAS 挂到 TestRun.gate_evaluation_id（竞态则回删评估行）
缺配不得默认通过：无 GateEvaluation + 明确 unevaluated_reason；not_evaluated 永远不是合法 result 枚举。

3. 仅报告 ⇄ 阻断（M2 Gate）

PATCH /api/v1/quality-gate-policies/{id}
{"expected_version": 3, "mode": "blocking", "confirm_blocking": true}
  • report_only：评估如实记 fail，但 Check Run conclusion=neutral，不阻断 CI。
  • blocking：fail → failure，阻断 CI exit。
  • 切换后新评估用新模式，历史评估行与其 conclusion 永不改写。

4. 豁免（gate_waiver）

fail 评估可由 owner/admin 经 API-120 发起 gate_waiver 审批（confirm:true），批准后挂 waiver_approval_id——result 保持 fail 不改，检索时按豁免过滤（result=waived 视图）。

5. 压测指标接入（FR-12 / M3）

# perf worker 终态后 result_summary.perf = {"p95_ms": ..., "error_rate": ..., ...}
# 同一管线内实测判定：actual <= threshold 才 pass；任一超阈 → fail
# 压测 run 无指标 → perf_report_missing（fail-close，不默认通过）
