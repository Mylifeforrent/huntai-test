integration_hub · 连接器与 Webhook

模块位置：backend/app/modules/integration_hub/。管「平台与外部系统怎么握手」：Connector（Jira/GitHub/CI/Release）、入站 Webhook 观察链、出站写动作（Jira 缺陷）、CI 触发绑定。

1. Connector（连接器）

字段说明
typejira / github / ci / release（org+type+name 唯一）
credential_ref只存引用（如 env:GITHUB_WEBHOOK_SECRET），真实值从 .env 解析；禁止明文入库
action_contract动作契约：sideEffectLevel / supportsPreview / Idempotency / Compensation
outbound_write_enabled出站写开关（P25 集成中心可关）
webhook_secret_ref入站验签密钥引用（env: 前缀白名单键）
config_version乐观锁；CI 触发绑定等引用它做 CAS

2. 入站 Webhook 观察链（API-090，G 纪律样板）

POST /api/v1/inbound-webhooks/{connector_id}      # 无认证头，HMAC 即身份
  1) 验签 x-hub-signature-256（失败 → 落观察 + 审计 + 401 HT-AUTH-004，仍不泄露密钥材料）
  2) 归属：connector → organization
  3) 去重：observation_key（connector+body+delivery+event）唯一
  4) 落 external_observations（Inbox event）      # 观察行是事实记录
  5) 按连接器类型分派内部命令：
       ci/github → run_command.apply_ci_observation → resume_ci_run_after_observation
       release   → release_command.apply_release_observation（SUBMITTED→READY / 迟到→divergence）
  ❌ 观察行禁止直接 UPDATE test_runs / release_tasks / gate_evaluations

3. 出站写动作（Jira 缺陷，FR-14）

# 1. 发起：从 FAILED run 的聚类/用例上发起

# 2. 审批（L2）
POST /api/v1/approval-requests/{id}/decisions  {decision: "approve"}
# 3. 执行钩子：execute_jira_write_after_approval → jira_write_stub（无真实 HTTP）
#    external_request_id = sha256(org:approval:bound_hash)（幂等）
#    成功写 append-only EvidenceObject（source_object.connector=jira）
  • CI 触发绑定 API-167：项目内 repository+ref_pattern → test_plan_id，PUT 全量替换 + CAS。
  • 报告采集（FR-18 M2）：Jenkins progressiveText 增量拉日志分片 → 报告适配器（junit/allure/playwright/pytest）→ 归一化 CaseResult。
