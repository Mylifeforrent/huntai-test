approval_policy · 审批与副作用分级

模块位置：backend/app/modules/approval_policy/。管「什么动作需要人点头」：ApprovalRequest 审批中心 + Policy Gate 副作用分级（FR-17）。

1. 副作用分级 L0–L4 与 Policy Gate

Tool Router（schema 校验 + 租户/角色）→ Policy Gate（按 sideEffectLevel 裁决）
  L0 / L1  → ALLOW
  L2       → REQUIRE_APPROVAL（创建 ApprovalRequest，等人工）
  L3 / L4  → REQUIRE_APPROVAL（并按窗口要求再认证）
  未声明   → DENY（默认拒绝！）
  白名单外 → DENY + 记录安全事件（不进审批）
action_ref级别用途
jira_writeL2创建 Jira 缺陷（自动附证据）
heal_applyL3应用定位器自愈（新 TestCaseVersion）
perf_high_riskL3高危压测配置执行（白名单外直接 DENY）
env_registerL3注册执行环境（ACTIVE 仅在 EXECUTED+ok 后）
gate_waiverL3门禁豁免（不改 result，挂 waiver_approval_id）
kill_switch_restoreL3恢复被关停的能力（放开必须走审批）
release_pushL4确认 Release 推送（内部 prepare，无生产发布 API）
agent_tool_action按声明Agent 工具动作（manifest 上限 ≤L1，M2 试点）
copilot_writeDISABLEDM4 前一律 DENY

2. 审批生命周期

POST /api/v1/action-previews            （API-120：九要素卡片 + param_hash 绑定）
  → PENDING（四眼：approver 从 owner/admin 候选中选，且 ≠ 发起人）
POST /api/v1/approval-requests/{id}/decisions   （API-112：approve/reject + expected_version CAS）
  approve → APPROVED → 执行钩子（各域 command_port）→ EXECUTED + execution_result=ok/failed
  reject  → REJECTED（部分动作联动取消领域对象）
  超期    → EXPIRED（懒过期；param_hash 失效也直接 EXPIRED）
APPROVED ≠ EXECUTED + ok。领域状态只能由执行钩子推进；模型声称「已获批准」不构成授权。

4. 九要素审批卡片

卡片（card_payload）展示：动作与目标 / 前后内容 diff / 数据来源、模型与 Skill 版本 / 风险等级色标 + 成本估计 / 回滚能力 / 参数哈希。前端 P10 审批中心只渲染卡片，不做本地裁决。
