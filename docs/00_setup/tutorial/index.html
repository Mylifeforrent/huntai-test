1. 这个项目是什么

HuntAI Test 是企业内部自用（≤1000 用户、部门级多租户）的 AI 自动化测试平台：以接口 / Web / 性能三大自动化域为核心，用 AI 做用例生成、失败聚类与归因、自愈建议，用确定性工作流、副作用分级、审批与证据链约束一切有副作用的动作，并与 Jira / GitHub / CI-CD / Release 打通形成质量闭环。

一句话架构：模块化单体控制面（FastAPI）+ PostgreSQL 事实权威 + 各域 Worker 子进程（Playwright / Locust / Agent）。控制面负责认证、租户、RBAC、审批、门禁、审计；Worker 只做执行，结果回写数据库。

3. 十分钟跑起来

# 1. 后端（Python 3.14 + uv）
cd backend
uv sync                                # 安装依赖
uv run alembic upgrade head            # 数据库迁移（需本地 PostgreSQL）
uv run uvicorn app.main:app --reload   # 启动 API（见 backend/README.md）

# 2. 前端（Node 24）
cd frontend
npm install
npm run dev                            # Vite 开发服务器（代理 /api 到后端）
红线提醒：仓库禁止 pip / requirements.txt / poetry / pnpm / yarn；配置只从根目录 .env 注入；.env 永不入库。

4. 合入前必须全绿的验证命令

# backend/
uv run ruff check . && uv run ruff format --check . && uv run mypy app && uv run pytest

# frontend/
npm run lint && npx tsc --noEmit && npm run build && npm run test

这是仓库的硬纪律：任何 AI / 人工生成的代码，验证命令不零失败禁止合入。

5. 必须先建立的心智模型

概念一句话解释深入阅读
五个状态机TestRun / TestCase / ApprovalRequest / ExecutionEnvironment / ReleaseTask 的状态只由后端裁决，前端只渲染执行编排、发布编排
23 个领域对象全部数据模型枚举在 problem_model.md，禁止新增第 24 个测试资产
受理 ≠ 完成202 + 回执只是「收到了」；完成以权威 GET / 可授权下载为准执行编排
引用 ≠ 授权object_key / artifact_id 不是下载令牌，每次代理下载都重验 RBAC结果与证据
L0–L4 副作用分级Policy Gate 按级放行 / 要求审批 / 拒绝；未声明默认拒绝审批与策略
错误码三类network / permission / business；跨租户一律 404 不泄露存在性开发工作流
