run_orchestration · 执行编排（核心模块）

模块位置：backend/app/modules/run_orchestration/。管「怎么跑」：TestRun 十态状态机、四条执行路径（script 接口 / Playwright Web / Agent / 外部 CI / 压测）、Worker 子进程、回执与 SSE。

1. TestRun 十态（唯一权威在后端）

[*] → PENDING → VALIDATING → RUNNING ─┬─▶ SUCCEEDED / FAILED（终态）
                    │                  ├─▶ WAITING_APPROVAL（遇 L2+ 动作；批准→RUNNING）
                    │                  ├─▶ WAITING_EXTERNAL（外部 CI；观察回填）
                    │                  └─▶ STOPPING ─▶ CANCELLED
                    └─▶ FAILED（校验失败/环境不可用等）
RUNNING 超过心跳窗口 ──僵尸回收──▶ TIMEOUT
  • 受理 ≠ 完成：API-062 返回 200 + 回执只是「已受理」；终态以 API-061 GET 为准，SSE（API-210）只是 hint。
  • 取消 ≠ 已取消：RUNNING 中取消先到 STOPPING（持久化 stop_signal_at），worker 消费信号后才落 CANCELLED。
  • 自动重试只适用于功能回归 run；压测与 Agent 任务禁止自动重试。

2. 四条执行路径（都在 VALIDATING 后分叉）

路径执行者要点

3. Worker 子进程模式（本仓库最重要的模式）

# executor.py 统一写法
proc = await asyncio.create_subprocess_exec(
    sys.executable, "-m", "app.modules.run_orchestration.<worker>", payload_path,
    cwd=str(Path(__file__).resolve().parents[3]))
out, err = await proc.communicate()      # worker 自行写库（CaseResult/StepRun/Artifact）
  • worker 是独立进程，没有 asyncio.create_task 跑 DB 的写法（仓库红线）。
  • 长生命周期任务（压测）为 fire-and-forget：executor 派生后即返回，避免受理请求被内联阻塞；收尾（终态/配额释放/门禁/排队晋升）由 worker 自己完成。
  • 心跳：update_test_run_status(..., heartbeat=True)；僵尸回收 reclaim_stale_active_runs 把超时 RUNNING 打成 TIMEOUT。

4. 受理纪律：幂等键 + 回执

POST /api/v1/test-runs
Idempotency-Key: <uuid>        # 必带；同 key 同哈希=重放原响应，不同哈希=409 HT-IDEM-001

→ 200 {"data": {"id": "...", "receipt": {"id": "receipt-uuid", "status": "accepted", ...}}}

GET /api/v1/command-receipts/{receipt_id}          # 回执查询（通用）
GET /api/v1/test-runs/{run_id}/events              # SSE 进度（只读 hint，禁止当命令通道）

command_receipts 表由 run_orchestration 托管，其他模块（证据导出、Release 重试）通过 command_port.create_command_receipt_for_command 跨模块落回执——跨模块只走 port（返回 dict），禁止 import 他模块 ORM。

5. 压测特有纪律（FR-11）

机制行为
白名单TARGET_ENV 必须命中场景参数 perf_whitelist 前缀；否则受理直接 HT-POL-002，不建审批
场景互斥同场景已有在途 run → 新 run 保持 PENDING（perf_queued）；终态后由 worker 晋升一个，永不并行施压
并发预算OrgQuota.perf_concurrency_in_use 占用/释放；耗尽 → run FAILED（perf_quota_exhausted）
kill switchworker 每 5s 查 tightened_modules 含 performance → 终止 Locust → CANCELLED（60s 窗口内）
abort_on_breach实时 p95/错误率超场景阈值 → 停止施压 → FAILED
压力机自监控psutil 采 CPU；施压机饱和与「目标慢」分开判定，写 perf_report
