identity_tenancy · 租户、认证与 RBAC

模块位置：backend/app/modules/identity_tenancy/。它是所有请求的第一道门：会话是谁、属于哪个组织、在项目里是什么角色，都从这里来。

1. 核心对象

对象说明
Organization租户。所有业务表都带 organization_id，查询必须带租户上下文
User由 IdP（OIDC）登录引入，本地只存 idp_subject 映射，不存密码
Project / ProjectMember项目及成员；角色（owner / admin / tester / viewer）挂在项目成员关系上，不是全局角色
AuthSession服务端会话；HttpOnly + Secure + SameSite Cookie，禁止写 localStorage
ApiToken机器身份：Bearer 头，库内只存 argon2 哈希，scopes ⊆ read/write/execute/delete，project_ids 白名单
OrgQuota / capability_controls组织级配额与 kill switch（见 quota_governance）

2. 认证通道（三条，各走各的门）

通道流程关键纪律
OIDC 会话（浏览器）API-001 /auth/oidc/start 生成 state+nonce+PKCE → IdP 登录 → API-002 callback 校验 → 发 Cookiecallback 必须校验 state/nonce/PKCE；浏览器永远不接触 IdP token 明文
ApiToken（机器）Authorization: Bearer ht_...，经 require_session_or_token_* 依赖项认证明文只在签发响应出现一次；scopes 与 project_ids 限权；禁止替代审批/Policy Gate
HMAC（入站 Webhook）API-090 /inbound-webhooks/{connector_id}，先验签再归属、去重、落观察观察行禁止直接改 TestRun / release_tasks 等领域表

3. RBAC：角色怎么参与鉴权

# 服务端每请求强制；前端置灰只是体验，不是安全边界
role = await identity_query.get_project_membership_role(
    session, organization_id=..., project_id=..., user_id=...
)
if role is None:            # 跨租户/跨项目：一律 404，不泄露存在性
    raise ValueError("not_found")
if role not in WRITE_ROLES: # 同租户但角色不够：403 HT-IAM-001
    raise ValueError("forbidden")
角色读写（用例/计划/Release）发起执行/压测审批/管理
owner / admin✅✅✅✅（且审批人 ≠ 发起人）
tester✅✅✅❌（可发起审批）
viewer✅❌❌❌
fail-close 纪律：凡是契约标注 TBD 的权限问题（如「viewer 能否导出」），一律拒绝并返回 HT-IAM-001，绝不发明默认放行。

4. 会话与再认证（step-up）

  • Cookie 名称 / TTL 由 .env（SESSION_COOKIE_NAME、SESSION_TTL_SECONDS）注入，代码不硬编码。
  • L3+ 高危动作超时窗口内要求再认证：返回 401 + HT-AUTH-002（REQUIRE_REAUTH）；完成后同一 Idempotency-Key 仅当请求哈希不变才可重放。
  • 登录态本身也是资源：API-003 登出、API-004 再认证、API-005 /me 返回用户 + 组织 + 成员关系。

5. kill switch（组织级关停）

API-199 POST /organizations/current/capability-controls/tighten（L1，即时生效，不走审批）：

{
  "expected_version": <org.aggregate_version>,
  "target": {"level": "module", "module": "copilot"},   // 模块码：copilot / performance ...
  "reason": "incident"
}
  • 关停（收紧）= L1 即时；恢复（放开）= L3，必须走 kill_switch_restore 审批，禁止用 tighten 放开。
  • 效果落 organizations.capability_controls（tightened_modules / tightened_capabilities 等），各模块在动作前自查——Copilot 提问、压测施压进程都会因此真实失败（AC-069）。
