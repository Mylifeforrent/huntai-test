release_orchestration · Release 编排（FR-15）

模块位置：backend/app/modules/release_orchestration/。管「怎么把质量证据变成一次可审计的发布准备」——平台只准备 release item，绝不执行生产发布。

1. ReleaseTask 六态状态机

[*] → DRAFT（Jira 版本圈定 + scope_snapshot 冻结）
      ──Readiness 评估 + A5 草稿就绪──▶ PENDING_CONFIRM
      ──release_push 审批批准（EXECUTED+ok）→ 内部 prepare──▶ SUBMITTED
SUBMITTED ──webhook 观察（item 创建成功回传）──▶ READY   # READY ≠ 生产已发布
SUBMITTED ──prepare 失败──▶ FAILED_RETRYABLE ──API-153 人工幂等重试──▶ SUBMITTED
PENDING_CONFIRM / FAILED_RETRYABLE ──API-154──▶ CANCELLED（迟到 READY 只追加 divergence）

2. 全链路 API

API说明
API-152 POST /release-tasks圈定版本 → DRAFT + 范围快照冻结（Jira 连接器缺失 → HT-EXT-001）
API-150/151列表 / 详情（快照、A5 只读、divergence、release_item）
API-155Readiness 投影：jira_scope / gate_evaluation / notes_draft 三项 + overall（后端评估，前端只呈现）
API-120/112release_push（L4）审批；批准 EXECUTED+ok → 内部 prepare（幂等键防重复创建外部 item）
API-153FAILED_RETRYABLE → 202 + Receipt → 后台重入 SUBMITTED；HT-EXT-002 禁盲重试
API-154取消（仅两态可取消）；CANCELLED 后迟到 READY 只追加 divergence

3. prepare 幂等（AC-067）

prepare_key = sha256(f"{org}:{task_id}:{sha256(scope_snapshot)}")
# item ref 表对 (organization_id, prepare_key) 唯一：
#   命中 → 直接幂等成功，不再调用 Release 连接器（外部 item 永不重复创建）
# prepare 是系统内部命令（审批执行钩子），没有「执行生产发布」产品 API

4. A5 Release Notes 草稿（只读）

{"summary": "...", "changes": [{"jira_key": "...", "type": "feature|fix|breaking", ...}],
 "checklist": [{"item": "...", "status": "pass|fail|missing", "evidence_ref": "..."}],
 "missing_inputs": ["jira_scope_issues"],   # 缺失项显式列出，禁止编造
 "meta": {"ai_invocation_log_id": "...", "degraded": true}}
AC-066：A5 草稿就绪 ≠ 可以推送；未经 release_push 审批 + 确认，平台不会调用 Release 系统。

5. READY 由观察驱动

prepare 只把任务推进到 SUBMITTED 并登记 release_item_refs；READY 只能来自 API-090 HMAC webhook 观察（release 连接器分派到 apply_release_observation）。观察链保证「先验签、去重、落观察，再经命令推进领域状态」。
